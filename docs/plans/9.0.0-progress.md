## Approved decisions (do not revisit)

- Three packages, all 9.0.0: `LokiBulkDataProcessor.Core` (new), `LokiBulkDataProcessor` (same id, SQL Server provider on
  Microsoft.Data.SqlClient 6.1.8), `LokiBulkDataProcessor.Oracle` (new, Oracle.ManagedDataAccess.Core 23.26.400).
- Breaking changes allowed; each gets a README upgrade-guide row. Keep type forwarders for types that move to Core.
- `IBulkProcessorFactory`: injectable, mockable singleton, `Create(string providerName, string connectionString)`.
  Registration: `AddLokiBulkDataProcessor(...).AddSqlServer().AddOracle(...)`; the legacy `AddLokiBulkDataProcessor(connectionString, ...)` keeps working.
- No capability flags in the SPI: every provider joins the caller's transaction. Writers have a single `WriteAsync`.
  Oracle direct path is synchronous (document as an Oracle API limitation).
- Oracle options: `WriteMode` ArrayBind (default) / DirectPath (opt-in); `IdentifierResolution` Unquoted (default) /
  CatalogLookup (opt-in); `BooleanBinding` Number (default) / Boolean. Minimum Oracle 19c; tests on `gvenzl/oracle-free:23-slim-faststart`.
- `IBulkProcessor.ConnectionString` is removed. The SQL integration test project keeps the name `LokiBulkDataProcessor.IntegrationTests`.
- Direct-path hazards to document: FKs not enforced; a duplicate PK leaves the index UNUSABLE; tables with triggers are
  refused; one load per transaction; `EnforceIndexChecks` hung in testing, never use it.

  - Deviations from the spec:
    1. `LokiLogging` is a sealed `IDisposable` class (not a record) with `LokiLogging.None`. It disposes the logger factory only
       when Loki created it (console). Console logging is used only when `LokiLoggingOptions.EnableConsoleLogging` is true.
       Otherwise selection falls through to the host factory (if opted in) or the no-op factory.
    2. `MappingRegistry(IEnumerable<Assembly>)` ignores null and repeated assemblies. It also has an internal
       `(IModelMappingCollection, IDataMappingCollection)` ctor and `MappingRegistry.Empty`. `ModelMappings`/`DataMappings` have an
       internal ctor that takes mapping `Type`s, because the unit-test assembly deliberately contains invalid mappings and tests can't scan it.
       A mapping that fails to instantiate is still wrapped in `InvalidOperationException`, which now keeps the cause as `InnerException`.
    3. The pipeline enforces #15 beyond the skeleton. If `TranslateException` returns null or the same exception, the original is
       rethrown with `throw;`. If the translation doesn't carry the original in its `InnerException` chain, it is wrapped as
       `InvalidOperationException(translated.Message, original)`.
    4. Step-3 follow-up "mapped get-only property": `BulkSource.FromModels` checks that every mapped source column is a copied
       property. If one isn't, it throws `ArgumentException` (`BulkCopyErrorMessages.SourceColumnNotFound(name)` plus a hint, `ParamName`
       `dataToProcess`) before any connection is opened. The check lives in `ColumnMapResolver.ThrowIfSourceColumnMissing`
       (not `MappingLogic/`) and applies to **models only**. The driver still validates DataTable/reader source columns, so the
       documented mapping message is unchanged. Skipped property **names** are logged at Debug.
    5. `BulkProcessor` keeps the 8.x `Setting BatchSize/Timeout` and `Setting/Clearing external transaction` Information logs.
    6. JSON: the redundant `TableName` guard is dropped, because `JsonSchemaValidator` already rejects a missing or empty `tableName`.
    7. `SqlServerBulkCopyProvider.AdoptExternalTransaction(null)` throws `ArgumentNullException`. The wrong-type
       `ArgumentException.ParamName` is now `transaction` (step 2 used `Transaction`). The check runs in the
       `Transaction` setter and again in `ConnectionScope`.
    8. The factory sanitises an unknown provider name before echoing it (`MessageText`), and (security review) no longer
       lists the registered names in the message; callers use `ProviderNames`.

    table that isn't in the README yet. That covers: ConnectionString/WithConnectionString removed; CancellationToken + ProviderName;
    per-instance settings (#11); caller transaction not rolled back (#12); InnerException (#15); DataMapping rule + `sourceName` (#16);
    duplicate mappings fail at startup; BulkProcessor internal; Commands/Context/InternalDbOperations/DbConstants removed;
    the three mapping-storage types internal; logging no longer app-wide; `AddLokiBulkDataProcessor` callable once only; Testcontainers and

    - The log category changes from `Loki.BulkDataProcessor.BulkProcessor` to `Loki.BulkDataProcessor.Internal.BulkProcessor`.
    - The log texts are new: `Starting/Completed bulk copy to {TableName} via {Provider}` and
      `Bulk copy to {TableName} via {Provider} failed with {ExceptionType} (inner {InnerExceptionType})`. The failure entry
      no longer carries the exception object (security review, below). Logged table names are sanitised.
    - Bulk-copy failures that are not a column-mapping mismatch now have a fixed message,
      `Bulk copy to '{table}' failed (SQL Server error {Number}). See InnerException for details.` (without the
      parenthesis when there is no `SqlException`), instead of the driver's message. The driver exception is the InnerException.
    - The unknown-provider `ArgumentException` no longer lists the registered provider names.
    - **New public API (additive):** `IBulkProcessor.SaveAsync(Stream jsonStream, string destinationTableName, CancellationToken)`;
      `LokiBulkDataProcessorOptions.RequireDataMappingForJson` (default false) and `LokiBulkDataProcessorOptions.MaxJsonPayloadBytes`
      (`long?`, default null = no limit); `BulkCopyErrorMessages.BulkCopyFailed(tableName)` and
      `BulkCopyFailed(tableName, databaseName, errorCode)`. `BulkCopyErrorMessages.SourceColumnNotFound` now sanitises its input.
    - JSON is parsed with explicit `JsonDocumentOptions` (`MaxDepth` 64, comments and trailing commas disallowed; same as the defaults).
    - SQL Server does not set `FireTriggers`: INSERT triggers do not run (documented on `SqlServerProvider` and `IBulkProcessor`).
    - The legacy overload throws `ArgumentException` for a blank connection string at registration.
    - Mappings are instantiated at registration, not at first resolve.
    - A model mapping of a get-only property throws `ArgumentException` before connecting.
    - `Transaction = null` clears the transaction instead of throwing.
    - `SaveAsync` argument guards throw synchronously.
    - The README still describes the 8.x API (no factory or builder docs).
  - **Security review fixes** (PR #23, after the code + security review):
    - Data-free errors (CWE-209/532): `SqlServerExceptionTranslator.Translate(exception, target)` builds
      `BulkCopyErrorMessages.BulkCopyFailed(table, "SQL Server", Number)` (the `SqlException` is searched along the InnerException
      chain) or `BulkCopyFailed(table)`; the column-mapping message is unchanged and fixed. The pipeline's fallback wrapper (a
      translation that drops the original) uses `BulkCopyFailed(table)` instead of the translation's message. The original is
      always the InnerException. A provider that returns null or the same exception still has the original rethrown (deviation 3).
    - Failure log: **choice recorded** - `BulkProcessor` logs the exception **type** and InnerException type, the sanitised table and the
      provider, and **not** the exception object, so no driver text reaches Loki's log. No SPI hook for a provider error code was added
      (keeps `IBulkCopyProvider` unchanged); the SQL Server error number is in the thrown exception's message. `ConnectionScope` still
      logs a rollback failure with its exception (it is swallowed otherwise, and rollback errors do not carry row data).
    - Connection string (CWE-200): `BulkProcessor._connectionString` is `[DebuggerBrowsable(Never)]`, the class has
      `[DebuggerDisplay("ProviderName = {ProviderName}")]` and `ToString()` returns `BulkProcessor ({ProviderName})`. The legacy
      `AddLokiBulkDataProcessor(connectionString, ...)` no longer captures the string in a lambda closure: a private
      `LegacyProcessorSource` holds it in a hidden field. The factory and `BulkProcessorSettings` hold no connection string;
      `BulkCallSettings` was already annotated.
    - Log forging (CWE-117): table names logged by `BulkProcessor` and `JsonDataReader` go through `MessageText.Sanitize`. The other
      log arguments are code-derived (type/property names, counts, provider names from registration).
    - JSON routing (CWE-639/915): new overload `SaveAsync(Stream, string destinationTableName, CancellationToken)`; the payload's
      `tableName` is still schema-validated but ignored, and the DataMapping key is `destinationTableName` (#16: no explicit source
      name, so the destination is the key). Opt-in `RequireDataMappingForJson` makes a JSON save with no matching DataMapping throw
      `InvalidOperationException` before connecting (both JSON overloads). The options reach processors via an internal singleton
      `Internal/JsonPayloadPolicy` that the factory passes on; the legacy registration can't set them (use the builder).
    - JSON size (CWE-400): opt-in `MaxJsonPayloadBytes` wraps the stream in `DataReaders/LengthLimitedStream`, which throws
      `InvalidDataException` as soon as the limit is passed (a seekable stream whose remaining length is over the limit is
      rejected before reading). The caller's stream is never disposed.
    - `SaveAsync(Stream)` guards throw synchronously; `BulkSource.FromJson` disposes the `JsonDataReader` if it throws, the processor
      also disposes it with `using`, and `JsonDataReader.Dispose` is idempotent.
    - Docs: `IBulkProcessor.Transaction` warns that some server errors doom the caller's transaction (check and roll back); the legacy
      registration recommends `IBulkProcessorFactory` for long-lived owners.
    - Tests: unit `BulkProcessorSecurityTests`, `Sources/BulkSourceTests`, `DataReaders/LengthLimitedStreamTests`,
      `Providers/BulkCopyErrorMessagesTests`, plus updates to the translator, pipeline, factory, registration and processor tests;
      integration `BulkProcessorJsonSecurityTests`, a SQL Server conversion-error test in `BulkProcessorLoggingTests`, and the #15
      test now asserts the fixed `(SQL Server error 547)` message.
  - **Code review fixes** (PR #23, the three code-review warnings):
    - `ConnectionScope.DisposeAsync` never throws. It disposes the owned transaction, then always the owned connection. Each
      dispose failure is caught and logged at Error with the exception **type** only (no exception object, no driver text). The
      write/commit error that is in flight under `await using` in `BulkCopyPipeline.ExecuteAsync` is therefore the one that
      surfaces. **Choice recorded:** dispose failures are also swallowed and logged on the success path, because the commit has
      already succeeded. A caller-owned transaction and its connection are still never disposed. `RollbackAfterFailureAsync`
      is unchanged: it still logs the rollback exception object, as recorded above.
    - If `IBulkCopyProvider.TranslateException` itself throws, the pipeline logs the translator's exception type at Error and
      throws `InvalidOperationException(BulkCopyErrorMessages.BulkCopyFailed(table), original)`, so #15 holds for any provider.
      This is preferred over `throw;` of the original because it keeps the caller-facing message fixed and data-free, as for a
      translation that drops the original; the driver error is still the InnerException.
    - Tests: `FakeDbTransaction`/`FakeDbConnection` got a `DisposeException` switch. New `BulkCopyPipelineTests` cover transaction
      dispose throwing after a write failure (original surfaces, connection still disposed), connection dispose throwing, both
      throwing after a commit failure, dispose throwing after a successful commit (call succeeds), a caller transaction that would
      throw on dispose (never disposed), and a throwing translator. 43 test methods added in this PR were renamed to
      `Member_Should<Outcome>_When/If<State>` (rename only).
  - `.claude/standards/dotnet-standards.md` still describes the 8.x layers (Commands/Context/InternalDbOperations), and step 9
    rewrites it. Until then, the CLAUDE.md layout/flow sections and these notes are authoritative.
  - Tests:
    - Unit: `Pipeline/BulkCopyPipelineTests`, a rewritten `BulkProcessorUnitTests` (mocked provider + fakes),
      `Factory/BulkProcessorFactoryTests`, `DependencyInjection/RegistrationTests`, `Mappings/MappingKeyTests`,

    - Integration: a new `BulkProcessorIssueFixTests` covers #11, #12, #13, #15 and #16, plus cancellation, BatchSize smaller than the row count,
      a DataTable with a Deleted row and the factory path. It uses the new mappings `PostImportDataMapping` and
